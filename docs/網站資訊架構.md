# EudTech 官網資訊架構

更新日期：2026-08-16
狀態：第一版開發中
適用分支：`codex/website-next-update`

## 1. 網站任務

EudTech 官網必須讓訪客在第一層就能辨識三種可購買能力：

1. 企業 AI Agent 與營運流程導入。
2. AI GPU 伺服器、工作站與液冷系統規劃。
3. 社群情報、假帳號與敘事風險分析。

網站導覽不再依首頁區塊或 SEO 頁面堆疊，而是依訪客任務組織。每一個主導航項目都必須對應可閱讀的總覽頁、可執行的下一步及可追溯的轉換入口。

## 2. 主導航

| 主分類 | 總覽頁 | 主要子項 | 主要行動 |
|---|---|---|---|
| 解決方案 | `/solutions` | AI Agent、AI 運算基礎設施、社群情報 | 選擇問題與導入路徑 |
| 產品與品牌 | `/products` | EudTech、Comino、Cyabra、FinSight | 查看產品、進入配置器 |
| GPU 選購 | `/resources` | 協助選型、直接配置、RFQ 與驗收、常用指南 | 選擇採購階段、建立配置、取得報價 |
| 關於 EudTech | `/about` | 公司定位、工作方式、人才招募、隱私 | 確認合作方式與公司資訊 |

全站固定行動：

- `配置 GPU 伺服器` → `/configurator`
- `預約諮詢` → `/contact`

Logo 一律回到 `/`。桌面使用四組主分類；平板與手機使用可展開、可捲動、可關閉的選單。

## 3. 實際頁面

### `/`

首頁依序呈現：明確價值主張、三大解決方案、產品與品牌入口、導入／採購方法、公司能力及最終諮詢。首頁不承載全部產品細節。

### `/solutions`

三大解決方案總覽。每張方案卡必須包含問題、輸出、適合對象及下一步，不能只放名稱。

### `/solutions/ai-agent`

保留現有完整 AI Agent 銷售頁：流程場景、來源、權限、人工核准、稽核、試點、驗收及諮詢。

### `/solutions/ai-infrastructure`

依「工作負載 → GPU／CPU／記憶體 → 電力與散熱 → 配置器 → 報價與交付」呈現 AI 伺服器服務，並連到採購資源及配置器。

### `/solutions/social-intelligence`

說明 Cyabra 支援的假帳號、敘事、影響力及風險分析，列出適用情境、交付流程及諮詢入口。

### `/products`

產品與品牌總覽，區分 EudTech 自有方案、Comino 液冷系統與 Cyabra。產品卡必須連到現有產品頁、解決方案頁或配置器，不能出現無路由的品牌連結。

### `/resources`

以「協助選型、直接配置、準備 RFQ」三個入口引導訪客，預設只呈現四篇常用指南。現有 17 個採購內容頁保留在可展開專題區、sitemap 與既有 `/solutions/<slug>`，避免破壞既有索引與外部連結。

### `/about`

說明優達盟公司定位、核心能力、工作方式與可驗證交付原則，並連到人才招募及聯絡頁。

### `/contact`

先讓訪客選擇 AI Agent、AI 運算設備或社群情報需求，再提供 Microsoft Bookings 與 `info@eudaemonia.tech`。

### `/privacy`

說明詢價資料、客戶來源追蹤、必要識別碼、保存與聯絡方式；不得宣稱尚未建立的法遵或刪除能力已經上線。

## 4. Footer

Footer 與主導航使用相同四組分類。Footer 可以列出較深層的採購指南及公司頁，但不顯示停用的 Blog、Press、無路由品牌頁或內部配置器連結索引。

## 5. 路由與搜尋索引規則

1. React route、導航、Footer、sitemap、feed、LLM discovery、社群預覽及靜態 SEO 頁必須一致。
2. 固定路由必須宣告在 `/solutions/:slug` 之前。
3. `/components-demo` 是內部元件展示，不進主導航及 sitemap。
4. 現有數字產品網址與 17 個採購內容網址先保留；建立語意網址前不得刪除或失效。
5. 每個新增公開總覽頁必須有獨立 title、description、canonical、Open Graph、結構化資料及 sitemap 項目。

## 6. 第一版驗收

- 桌面、平板及手機都能完整開啟四組導航與兩個行動。
- 所有主導航、子導航及 Footer 連結回傳成功頁面，不產生空白或錯誤 route。
- 首頁及每個總覽頁包含實際內容與下一步，不只顯示分類名稱。
- `/solutions` 不再只是一組 GPU SEO 卡片。
- `/resources` 能看見現有 17 個內容頁的任務分組。
- build、TypeScript、discovery、靜態 SEO 與路由驗證通過。
- 開發分支建立獨立預覽；取得使用者核准前不部署正式站。
