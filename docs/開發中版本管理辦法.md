# 開發中版本管理辦法
## 目的

本辦法規範 EudTech 官網每次更新從開發、預覽、核准、正式發布到回復的最小流程。核心原則是：

> 開發中版本與正式版本分離；只有使用者明確核准正式發布後，更新才能進入正式站。

## 最小版本結構

- `main`：正式站唯一來源，只保存已核准並已正式發布的內容。
- `codex/<更新名稱>`：每次更新使用一個獨立分支，例如 `codex/update-ai-agent-page`。
- 預覽網址：每個更新分支對應一個獨立預覽版本，不影響正式站。
- 正式版本標籤：每次正式發布建立不可變 Git Tag，格式為 `vYYYY.MM.DD-NN`，例如 `v2026.08.16-01`。

不建立長期 `develop` 分支。每次更新直接從最新 `main` 建立短期更新分支，降低同步與合併成本。

## 分支切分原則

- 使用者每次提出一項網站修改，就建立一個獨立更新分支；修改只有一個字元時也適用。
- 使用者在同一句指示中要求的多項修改，視為同一批更新並放在同一分支。
- 使用者針對同一預覽版本指出錯誤、跑版或功能不正常時，修正留在原分支，直到該預覽版本可再次確認。
- 每個更新分支各自產生預覽版本、保存提交紀錄並執行驗證。
- 準備正式發布時，只合併使用者已明確判定可以上線的更新分支。

分支用來隔離每項修改；commit 用來保存該分支內每次修正；預覽部署用來提供可操作、可觀察的驗收版本。

## 三種狀態

每次更新只能處於下列一種狀態：

1. `製作中`：正在修改或驗證，正式站維持不變。
2. `預覽待確認`：預覽網址已可驗收，尚未取得正式發布核准。
3. `已正式發布`：使用者已明確核准，更新已合併至 `main` 並完成正式站讀回驗證。

「程式已完成」、「建置通過」、「預覽可用」、「已合併」與「已正式發布」是不同狀態，不得互相代替。

## 每次更新的固定流程

### 1. 建立更新版本

1. 讀取最新 `main`。
2. 建立 `codex/<更新名稱>` 分支。
3. 保存使用者原始指示。
4. 記錄本次更新範圍、驗收條件及不在範圍內的項目。

### 2. 開發與自動驗證

1. 只在更新分支修改。
2. 執行與變更風險相符的建置、功能、SEO、連結、表單及響應式驗證。
3. 有操作畫面的更新必須驗證電腦版與手機版。
4. 驗證失敗時維持 `製作中`，不得提供正式發布建議。

### 3. 產生預覽版本

驗證通過後產生獨立預覽網址，狀態改為 `預覽待確認`。交付內容固定包含：

- 預覽網址
- 修改內容
- 驗證結果
- 已知限制
- 預計正式版本號

預覽版本不得取代、覆寫或重新部署正式站。

### 4. 使用者上線判定

正式上線由使用者自行判定。使用者是否滿意、是否仍有設計想法，以及該版本能否正式上線，是三項分開處理的狀態。

只有使用者明確表示「這版可以上線」、「驗收通過」、「正式發布」、「上線」、「部署正式站」或語意完全相同的指示，才構成正式發布核准。取得正式發布核准後，AI Agent 必須依正式發布流程立即部署，不等待其他設計想法。

使用者明確表示「這版不能上線」時，該更新分支維持 `製作中` 或 `預覽待確認`，並依使用者指出的問題繼續修正。

「做」、「繼續」、「完成」、「做在網站上」、「幫我優化」及對預覽內容的討論，不構成正式發布核准。

使用者提出意見但未明確表示能否上線時，AI Agent 不得自行推定正式發布核准或拒絕；正式站保持不變。

### 5. 正式發布

取得核准後：

1. 將核准的更新分支合併至 `main`。
2. 由正式部署流程發布 `main`。
3. 建立 `vYYYY.MM.DD-NN` 正式版本標籤。
4. 讀回正式網站的版本、主要頁面、核心功能及行動版結果。
5. 將狀態改為 `已正式發布`。

正式發布回報固定包含：

- 正式網址
- 正式版本號
- 發布時間
- 驗證結果
- 上一個可回復版本

## 回復辦法

使用者要求「回復上一版」時，重新部署上一個已驗證的正式版本標籤。回復不刪除後續提交、分支、標籤或歷史紀錄。

回復完成後必須讀回正式站，確認：

- 正式版本已切換
- 主要頁面可開啟
- 核心功能正常
- 上一個問題版本不再提供正式流量

## AI Agent 執行契約

任何 AI Agent 處理 EudTech 官網更新時，必須遵守本辦法。AI Agent 可以自行完成分支建立、程式修改、自動驗證及預覽部署；AI Agent 未取得使用者的明確正式發布核准前，不得合併 `main`、建立正式版本標籤或部署正式站。
